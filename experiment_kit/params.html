RegionFlash の指定（cachesim の -e）の解説

experiment_kit の config.sh に並ぶ構成の文字列の読み方。admit・hint の引数表（§5・§6、11 + 17 種・引数 190 個）は、ビルドした libCacheSim から読み出したもの（tools/synth/build_params_doc.sh で作り直せる）。それ以外は手で書いた説明（2026-11-19、libCacheSim 93529a1 ＋ regionflash.patch）。

一言　構成の文字列は「どこで何を決めるか」を順に並べたもの。DRAM から出たコンテンツを 書くか（admit）、どの口に書くか（hint）、どの Region を消すか（region-evict）、消すとき何を書き直すか（reinsert）の 4 か所に、それぞれ方式と引数を指定する。

1. 全体図：指定がどこに効くか

2. 書き方の規則

  • cachesim の形：cachesim <トレース> oracleGeneral RegionFlash <SSD 容量> -e "key=値,key=値,…"。最後の数（位置引数）が SSD の容量。
  • 最上位はカンマ , 区切り。方式に引数を付けるときは 方式:引数=値/引数=値 と、中を スラッシュ / で区切る（例 reinsert=hits:n=auto/target=0.5、hint=key:key=dram/k=2）。
  • region-evict の引数だけは別のキー region-params= に書く（例 region-evict=lru,region-params=auto=1/w=0.1）。
  • 大きさは K・M・G・T（2 進。64K = 65536）。境界の並びもスラッシュ（hint=fixed:64K/1M）。
  • 同じキーを 2 度書くと後の値が使われる（kit の paper は、Region の大きさを各行で上書きしている）。知らないキーを書くと、cachesim はエラーで止まる。

4. 消すとき書き直す：reinsert=方式:引数

Region を消すとき、その中でまだ有効なコンテンツを、開いている Region へ書き直して残すか。書き直すほど BMR は下がるが SSD 書き込み（アプリ層の書き込み増幅）が増える。

引数既定意味kit での値

n1hits の閾値。n=auto で分類ごとに自動（書き直したものが次の滞在でも当たった割合が target 以上になる最小の n。1〜8）。1 / 3 / auto

5. どの Region を消すか：region-evict= と region-params=

消すのはいつも封じた Region 1 つ丸ごと（開いている Region は消さない）。引数は region-params に / 区切りで書く。

region-evict引数意味
fifo—いちばん先に封じた Region を消す。
lrufc, ff, auto, w, win, step, gate, …いちばん長く触られていない（書いた・SSD で当たった）Region を消す。
fc=1/ff=0.9：分類 fc（1 = 大）の Region が全 Region の ff 以下なら、fc の Region は消さずに他の分類の最古を消す（fc の下限）。ff=0 なら普通の LRU。
auto=1/w=0.1：下限 ff を走りながら山登りで決める。win 回の消去（既定 4N。N = Region 数）ごとに J = BHR + w·OHR を測り、上がれば同じ向きに step（0.02）動かす。w=0 なら BHR（= 1 − BMR）だけ。ff の初期値は分類 fc が書いたバイトの割合。
gate=1（auto=1 と）：まず下限なしで始め、ときどき 1 窓だけ下限を試して、J が上がると分かったときだけ山登りへ（gd・gm・gz・gneed・gk・gkmax・gback はその試しの細かい設定。ru_auto_guide.html §6）。
betabeta分類ごとの LRU の末尾のうち、（古さ）×（小さい分類の平均の大きさ ÷ その分類の平均）^beta が最大のものを消す。beta=0 は lru。
mvw, tail, half, min分類ごとの Region の LRU の末尾のヒット密度（限界価値）を比べ、いちばん低い分類の末尾を消す（BHR + w·OHR の静的分割の最適条件に近づく）。tail = 末尾の何 Region を見るか（2）、half = 減衰の半減期（N 回の消去）、min = 分類が残す最小の Region 数（1）。
sfiforatioCacheLib の SegmentedFifo：分類ごとの段に分けた FIFO（ratio=1:1 で段の重み）。
glwindow, sample, hist, rank-intvl, label, warm, …GL-Cache の学習（Region の特徴から価値を予測して低いものから消す）。
oraclerank-intvl将来の次のアクセスから、価値がいちばん低い Region を消す（上限。分析用）。
lcs:<名前>—libCacheSim の任意のアルゴリズムを、Region を大きさ R のコンテンツとみなして使う。

config.sh の 1 行（paper の ru_auto）を、run.sh が足す共通部分と合わせて分解するとこうなる。

dram-size=8G,chunk=64K,dram-algo=lru,inclusion=cachelib,seal-on-repartition=inactive,seed=1,interval=10000   ← run.sh が全構成に付ける

id読み方
