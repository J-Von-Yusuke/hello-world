RegionFlash 引数一覧

2026-10-19。libCacheSim に足した二段フラッシュキャッシュ RegionFlash に渡せる引数をすべて並べる。設計と検証は regionflash.html、変更点は regionflash_changes.html。表の既定値と制約はソース（RegionFlash.c の rf_parse、各プラグインの param_spec_t）から写した。

質問への答え
  • DRAM と SSD のアルゴリズムに別々の引数を渡せるか → 渡せる。 dram-params= は DRAM 層のアルゴリズム、ssd-params= は SSD 層（物単位モード）のアルゴリズム、region-params= は Region を選ぶアルゴリズム（region-evict=lcs:名前）に、それぞれ独立に渡る。実際に走らせて確かめた（§4.1）: DRAM の S3FIFO の引数を変えると DRAM の OMR が動き、SSD の S3FIFO の引数を変えても DRAM の OMR は 0.8031 のまま SSD の OMR だけが動く。
  • split_threshold の引数を変えられるか → 変えられる。 hint=split_threshold:lambda=128/min_band=3/recalc=50000 のように、8 つの引数（lambda・min_band・no_split_pct・recalc・ema_den・size_add・hyst_hold・hyst_band）をすべて指定できる。どれも効くことを確かめた（§5.1）: 既定の閾値 32K が、lambda=256 で 64K、recalc=10000/ema_den=4 で 16K、min_band=8 で「分けない」に変わる。

1. どの引数がどこに効くか（図 1）

1 要求は左上から右へ流れる。DRAM でミスした物は DRAM に入り、DRAM から追い出された物（victim）が受け入れ方針とヒントを通って SSD に書かれる。引数は、その流れのどこに効くかで分かれる。

2. 書き方の規則

./bin/cachesim <トレース> <形式> RegionFlash <SSD の大きさ> [libCacheSim の引数] -e "<RegionFlash の引数>"

例: ./bin/cachesim w01.oracleGeneral.bin.zst oracleGeneral RegionFlash 240gb \
      -e "dram-size=4G,dram-algo=s3fifo,dram-params=small-size-ratio=0.05,region-size=626M,hint=split_threshold:lambda=128,out=out/w01"
規則中身
-e の区切りキー=値 を , でつなぐ。キーの大文字・小文字は区別しない。同じキーを 2 回書くと後の値が勝つ。
入れ子の区切りは /-e 全体が , で区切られ、しかも libCacheSim の CLI が -e の中の ; を , に置き換えるので、値の中の区切りには / を使う。
  • dram-params・ssd-params・region-params: / はすべて , に戻してアルゴリズムに渡す（dram-params=small-size-ratio=0.1/move-to-main-threshold=2）。
  • hint=・admit=: 名前:k=v/k=v。/ は、次に 名前= が続くときと、数どうしの間（fixed:16K/64K、hr=20%/40%）だけ区切りとみなす。ファイルの道筋の / は壊さない（profile:path=/data/w01/sizebin_profile.csv/k=3）。
  • reinsert=: hits:n=1/max_frac=0.5/mode=ii。
大きさ-e の中は 2 進の接尾辞 K・M・G・T（4G = 4 GiB、626M、1.5K。4MiB も 4 MiB と読む）。位置引数の SSD の大きさは libCacheSim の書き方（64mb、240gb。これも 2 進）。240GiB と書くと CLI は数字だけ読んで 240 B になるので注意。
リストヒント・受け入れ方針のリストは / で区切る（fixed:4K/64K/1M、hr=20%/40%/60%/80%）。% は割合。
誤りの扱い知らないキーや値は黙って無視せず、起動時に止まる（下の表。どれも実際に走らせて確かめた）。
今の値を見るP.json の config・hint・admit に、既定値で補った後の値がすべて出る。中のアルゴリズムの値は dram-params=print（他の引数の後に /print でもよい）で表示して終わる（S3FIFO など print に対応したアルゴリズム）。
誤り例結果

4. 中のアルゴリズムの引数（dram-params・ssd-params・region-params）

RegionFlash は層ごとに libCacheSim のキャッシュを 1 つずつ作る。dram-params は DRAM 層、ssd-params は SSD 層（物単位）、region-params は Region を選ぶキャッシュ（region-evict=lcs:名前）に、/ を , に戻してそのまま渡る（libCacheSim の -e に書くのと同じ）。3 つは互いに独立で、同じアルゴリズムを違う引数で使い分けられる。

5. ヒントの引数（hint=名前:k=v/…）

ヒントは SSD に書く物の分類（書き込み系列。FDP では RUH = 分類 mod ruh）を決める。P.json の hint に、既定値で補った後の引数がすべて出る。「受け入れ数」は SSD への書き込み（on_insert）の回数、「要求数」は要求の回数。

5.1 split_threshold・st_recursive・split_threshold_req

研究者の SplitThreshold（split_threshold.h、改変なし）。大きさの log2 のバケットごとに個数・バイト・cold のバイトの 3 本のヒストグラムを持ち、recalc 回ごとに閾値 τ を決め直す。大きさが τ より大きい物を分類 1 にする。

引数既定意味
lambda0λ × 256（0〜256）。0: mid（count_p50 と byte_p50 の対数の真ん中）/ 256: min_rule = min(byte_p50, cold_byte_p50)（C 版の既定）/ 間は対数で補間。cold は λ > 0 のときだけ効く
min_band2狭帯ゲート（オクターブ）。byte_p50 − count_p50 がこれ未満なら分けない
no_split_pct5大 pool ゲート（%）。τ のバケットより上のバイトがこれ未満なら分けない
recalc100000再計算の間隔。split_threshold・st_recursive は受け入れ数、split_threshold_req は数えた要求数
ema_den16再計算のたびにヒストグラムを (ema_den − 1) ÷ ema_den 倍に減らす（実効の窓 ≒ ema_den × recalc）
size_add0数えるとき各物の大きさに足すバイト（Navy の serializedSize の近似）。τ は足す前の大きさに直して使う
hyst_hold1ヒステリシス: 同じ向きの候補がこの回数続いたら採用（1 = すぐ採用）
hyst_band0ヒステリシス: 採用中の τ からこのオクターブ未満しか動かない候補は無視（0 = 無効）
depth2（st_recursive）/ 1（split_threshold_req）st_recursive と split_threshold_req だけ。同じ規則で範囲を再帰的に分け、最大 2depth 分類
scopeallsplit_threshold_req だけ。all: 全要求を数える / ssd: SSD まで来た要求（DRAM ミス）だけ

数える場所の違い。 split_threshold と st_recursive は SSD へ書いた物を数え、ヒットせずに SSD から出た物を cold とする（物で数える）。split_threshold_req は要求を数え、ミスした要求を cold とする（要求で数える。違いと実測は regionflash.html §2.3）。

oracle_keyinfowindow（1000000）・W（0）・events分類しない。鍵と未来の値の相互情報量を P.json の hint_result に書く

7. libCacheSim の CLI の引数（関係するもの）

引数意味（RegionFlash での扱い）

8. 起動時の確認（組み合わせの制約）

次の組み合わせは、走らせる前に理由を書いて止まる。

条件理由
N（Region の数）< 分類数 + 2分類ごとの OPEN Region と、追い出しの余地が要る
chunk > region-sizeピースがどの Region にも入らず止まらなくなる
ssd-mode=object で chunk・ru-size・region-evict（lru 以外）Region モードだけの機能
ru-size が region-size の倍数でない／ruh=0／RU が足りないFDP の配置ができない（raise fdp-op）
reinsert の class=reclassify で hint_on_reinsert=no分類し直すにはヒントに知らせる必要がある
reinsert の mode=ii と class=reclassifyii はすべての書き直しを 1 本の系列に入れる
reinsert の n=0 と p=1追い出しのたびに全部書き直し、空きができずに止まらなくなることがある
reinsert の max_frac・p が (0, 1] の外—
ssd-mode=object で reinsert の mode=ii・class=reclassify・n=0物単位ではその場で入れ直すだけ
ヒントの分類数 > 64（mode=ii なら 63）分類は 1 バイトで持つ
層のアルゴリズムに RegionFlash、または知らない名前—

走らせている間も、要求ごとに「RegionFlash が数えた中身のバイト ＝ 中のキャッシュが持つバイト」を確かめる。追い出しを知らせないアルゴリズムは、ここで理由を書いて止まる（regionflash.html §3）。

8b. どの引数をどう確かめたか

方法通した引数
参照モデルとの差分テスト（diff_ref.py、300 ケース）inclusion（3 方式）、region-evict=fifo・lru・lcs:fifo、chunk、ssd-mode=object・ssd-algo、FDP（ru-size・ruh・fdp-iso・fdp-op・fdp-trim）、reinsert の n・max_size・max_frac・mode、dram-size=0、dram-policy / dram-algo
cachesim 本体との照合（plugin_cmp.py、30 構成）ヒント 12 種・受け入れ方針 9 種とその引数、reinsert の class=reclassify・hint_on_reinsert
cachesim 本体との照合（param_verify.py、11 構成）region-evict=beta と beta（0・1・−1・2.5）、reinsert の p（n=0 の割合方式、mode=ii、物単位モード）、warmup-req、seed（prob・adaptsize）
同じになるはずの書き方の比較（param_verify.py）taus と fixed:、region-evict=s3fifo と lcs:s3fifo、beta=0 と lru、out と prefix、大きさの書き方（8MiB・8M・8388608・0.0078125G、1.5K・1536）、-a size と admit=sizemax
cachesim との照合での指定plugin_cmp.py・trace_cmp.py・param_verify.py は seal-on-repartition=inactive を付けて cachesim の既定に合わせる（10-19 に既定を none に変えたため）
効き目の確認（§4.1・§5.1）dram-params・ssd-params・region-params、split_threshold 系の全引数、seed を変えると結果が変わること、interval=0

10-19 の確認で、reinsert の p < 1 が cachesim と食い違う誤りを見つけて直した。RegionFlash は再挿入のコインを独自の乱数で振っていたため、p < 1 では書き直す物が cachesim と違っていた（OHR で 0.001〜0.003 の差）。cachesim と同じ系列（seed·6+6）に変えて、4 構成とも全カウンタが一致した。

9. 例

# DRAM は S3FIFO（小さな FIFO を 5%）、SSD は Region、split_threshold を細かく調整
./bin/cachesim w01.oracleGeneral.bin.zst oracleGeneral RegionFlash 240gb -o runs/a.cachesim \
  -e "dram-size=4G,dram-algo=s3fifo,dram-params=small-size-ratio=0.05/move-to-main-threshold=1,\
region-size=626M,chunk=1M,hint=split_threshold:lambda=128/recalc=50000/ema_den=8/hyst_hold=2,\
interval=1000000,prefix=runs/a/w01"

# SSD を物単位にして SLRU（2 段）、DRAM は LRU
./bin/cachesim w01.oracleGeneral.bin.zst oracleGeneral RegionFlash 240gb -o runs/b.cachesim \
  -e "dram-size=4G,ssd-mode=object,ssd-algo=slru,ssd-params=n-seg=2,prefix=runs/b/w01"

# 消す Region を S3FIFO（引数つき）に選ばせ、要求で数える SplitThreshold（SSD まで来た要求だけ）
./bin/cachesim tencent.oracleGeneral.zst oracleGeneral RegionFlash 10gb -o runs/c.cachesim \
  -e "dram-size=165M,region-size=64M,region-evict=lcs:s3fifo,region-params=small-size-ratio=0.2,\
hint=split_threshold_req:scope=ssd/depth=2,prefix=runs/c/tencent"

# FDP（RU 4 Region 分、RUH 4、GC は元の RUH ごと）と再挿入（1 回以上ヒットした物、半分まで）
./bin/cachesim tencent.oracleGeneral.zst oracleGeneral RegionFlash 10gb -o runs/d.cachesim \
  -e "dram-size=165M,region-size=64M,chunk=1M,hint=st_recursive:depth=2,ru-size=256M,ruh=4,fdp-iso=pi,\
fdp-op=0.35,reinsert=hits:n=1/max_frac=0.5,warmup-req=5000000,prefix=runs/d/tencent"

シェルの行の継ぎ目（\）は -e の文字列の途中でも使えるが、空白を入れないこと（, の後の空白は読み飛ばすが、キーの前後の空白は読み飛ばさない）。
